# i18n do Frontend

Idiomas suportados: **pt-BR (padrão)**, **en** e **es**, com fallback para
pt-BR quando uma chave não existe no idioma ativo.

## Provedores

`src/app/app.config.ts`:

```ts
provideTranslateService({ fallbackLang: DEFAULT_LANGUAGE }); // ngx-translate 18, API funcional
provideTranslateHttpLoader({ prefix: "/assets/i18n/", suffix: ".json" });
```

Traduções em `frontend/public/assets/i18n/{pt-BR,en,es}.json` (servidas como
assets estáticos). Chaves agrupadas por domínio: `app.*`, `nav.*`,
`dashboard.*`, `orders.*`, `catalog.*`, `status.*`, `errors.*`, `toasts.*`,
`common.*`.

## LocaleService (`core/services/locale.service.ts`)

- `DEFAULT_LANGUAGE = 'pt-BR'`; `SUPPORTED_LANGUAGES` e `LANGUAGE_LOCALES`
  (mapa idioma → locale do Angular, ex.: `'pt-BR' → 'pt'`).
- Persiste a escolha em `localStorage` sob a chave **`app-language`**
  (constante exportada `LANGUAGE_STORAGE_KEY`).
- `resolveInitialLanguage()` — storage → `pt-BR`.
- `initialize()` roda no `APP_INITIALIZER` (garante idioma antes do primeiro
  render) e expõe o locale atual como **signal**.
- `LOCALE_ID` é fornecido por factory a partir do idioma inicial; a troca em
  runtime é reativa nos pipes customizados (que leem o signal do serviço), sem
  recarregar a página.

## Locales nativos

`registerLocaleData` para `pt`, `en` e `es` (top-level em `app.config.ts`) —
necessário para `CurrencyPipe`/`DatePipe` com locale não-en. O locale `'pt'`
cobre `'pt-BR'` por fallback do Angular.

## Pipes

| Pipe                     | Uso                     | Observação                                                   |
| ------------------------ | ----------------------- | ------------------------------------------------------------ |
| `TranslatePipe` (`\| t`) | `{{ 'app.name' \| t }}` | Wrapper fino sobre `TranslateService.instant`                |
| `StatusLabelPipe`        | status do pedido        | `status.<CÓDIGO>` ou o código bruto se não houver chave      |
| `AppCurrencyPipe`        | valores monetários      | `CurrencyPipe` com locale do `LocaleService`; digits `1.2-2` |

Atenção em asserts de teste: o formato pt-BR usa **NBSP** (`U+00A0`) como
separador de milhar — use `normalizeText()` do helper de teste.

## Troca de idioma

`LanguageSelectorComponent` no header (`layout/header/`) chama
`LocaleService` → `TranslateService.use()` + atualização do signal de locale.
Todos os textos e formatos de moeda reagem na hora.

## Testes (`src/testing/i18n-testing.ts`)

- `provideTestingI18n()` — `provideTranslateService` com `fallbackLang` igual
  ao da aplicação e **loader síncrono** (`TestingTranslateLoader`) que serve os
  **JSONs reais** de `public/assets/i18n/` (sem HTTP e sem duplicar chaves).
- `initI18nForTest(language = 'pt-BR')` — limpa o storage, aplica o idioma e
  aguarda `LocaleService.initialize()`. Chame no `beforeEach` após
  `configureTestingModule`.
- `normalizeText(text)` — troca NBSP por espaço comum.

Exemplo mínimo:

```ts
TestBed.configureTestingModule({
  imports: [OrderListPage],
  providers: [provideRouter([]), ...provideTestingI18n()],
});
await initI18nForTest();
```

## ng-bootstrap

Os templates do ng-bootstrap usam mensagens `$localize` (ex.: aria-labels de
paginação e toast). O polyfill `@angular/localize/init` está configurado em
`angular.json` (build target) e é herdado pelo runner de testes; a dependência
`@angular/localize` é explícita no `package.json`.
